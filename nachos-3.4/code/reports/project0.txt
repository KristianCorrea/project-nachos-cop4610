Thread class:
The Thread class stands for one thread of execution in Nachos. It keeps
things like the thread's stack, saved registers, whether it is running,
ready, or blocked, and a name for debugging. You create a Thread object,
then call Fork to start it. Yield lets another thread run, Sleep puts the
thread to sleep, and Finish ends it. If the thread runs a user program, it
also has space for that program's registers and address space.

Thread class:
The Thread class in Nachos represents a single thread of execution, storing
everything needed to save and restore the thread's state during a context
switch. Each thread holds a stack pointer, an array of saved CPU register
values, a pointer to its private execution stack, a status field, and a debug
name. Threads are created in two steps: allocating the thread object, then
calling Fork() to start it running a given function. Other key operations
include Yield() to give up the CPU, Sleep() to block, and Finish() to mark the
thread as done. If the thread is running a user program, it also stores a
separate set of user-level registers and a pointer to its address space, since
user threads need distinct register state for kernel mode vs user mode.
